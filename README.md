# GETWAB Federal Procurement AI for Claude

Local package v1.0.0, governed by GETWAB Canon v1.0.0.

## What is ready

A Claude Code plugin with a native remote HTTP MCP connection, research skills,
an executable offline field adapter, generated upstream schemas and query playbooks,
and reproducible ZIP builds. No server process, API key, SQL credentials or new
account database is bundled. The existing GETWAB server executes all research and
retains its existing account, entitlement and logging behavior.

## Local preparation

From the repository root:

```sh
python3 plugins/getwab-claude/scripts/package.py build
python3 -m unittest discover -s plugins/getwab-claude/tests -v
```

Build reads the current PHP tool declarations without booting Laravel or querying
databases, copies the authoritative Canon and 13 published playbooks, validates
skill references, and produces archives under this package's dist directory.
Generated files are reproducible; do not edit generated references manually.

To load later in an already configured Claude Code installation:

```sh
claude --plugin-dir ./plugins/getwab-claude
```

Use /mcp to inspect the connection and authenticate through the client's native
OAuth flow. A local URL example is in config/mcp.local.json; it is not loaded by
default. Keep HTTPS verification enabled; a local certificate must be trusted.

## Claude web / Desktop remote connector

A custom connector accepts the public MCP URL from .mcp.json. Adding that URL
does not by itself upload local skills or execute Python. The standalone skill
ZIP generated by the build contains its own references and can be uploaded where
the Claude product supports custom skills. Enable that skill with the connector.
The Claude Code plugin ZIP is a different artifact; do not upload it as a skill.

The direct connector retains upstream wire field names for compatibility.
The semantic map and executable adapter are local, not a newly deployed remote
normalization service. Native MCP calls are not intercepted by this package.
When filesystem execution is available, the research skill can normalize a saved
response using adapter.py; otherwise it uses the same field map while reasoning.

## Authentication and release limits

For the Claude custom connector choose **Required when the server asks** and
**No client ID — register one automatically** (DCR). Hosted client metadata (CIMD)
is not implemented by GETWAB. The local server change permits exactly the hosted
Claude callbacks on claude.ai and claude.com at /api/mcp/auth_callback, alongside
the existing ChatGPT callback. Deploy that change before testing against the
public URL; building this archive does not deploy it. No client secret is needed.

Native OAuth tokens belong to Claude's credential store. Never paste tokens,
passwords or client secrets into this package. Guest/registered/paid decisions
come from GETWAB; registration occurs in its existing web flow. A connection
challenge must stop research, not trigger anonymous retries or alternate sources.
No claim is made that Claude supports the server's delayed OAuth challenge until
tested in the actual client. If it does not, resolve that compatibility separately.

No Claude CLI/client is installed or authenticated by the build. End-to-end
authentication, free-limit enforcement, live evidence quality, and UI rendering
remain acceptance checks after registration. Offline tests cannot prove them.

## Maintenance

Change the root Canon first for semantic changes. Update mappings.json and its
tests, rebuild, and review compatibility exceptions before releasing an adapter.
The existing ChatGPT package and production controllers are not build targets.
